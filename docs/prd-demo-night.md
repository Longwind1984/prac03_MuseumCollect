# PRD — Demo Night (Scope-Limited, D0 → D1)

> 这是今晚跑的 mini-PRD,只覆盖 3 版高保真 HTML demo 的范围。
> 完整 PRD (`docs/prd.md`) 在 C1 之后再写,基于今晚 audit 综合结论。

---

## 1. Target User Persona

### 硬核博物馆爱好者(Core User — 一类人,三种切面)

**画像基线(所有 3 个 Builder 共享的底层假设)**

- **年龄**: 18-38,以一线/新一线城市为主
- **行为特征**:
  - 一年至少进博物馆 5 次以上;出差/旅行先查当地博物馆
  - 看展前会做功课,看展中会拍展签 + 文物,看展后会想"再回顾一次"但通常没下文
  - 已经关注至少 1 个文博类公众号 / B 站 UP 主 / 小红书博主
  - 朋友圈/小红书发过博物馆相关内容,期待被认出"懂行"
- **核心动机**: 不是消费"美图",而是想构建**自己的认知地图** —— "我看过的、我懂的、还没看的"
- **当前痛点 (Top 5)**:
  1. **看完就忘**: 一年看 20 件文物,3 个月后只记得 3 件,缺一个"我的博物馆履历"
  2. **维度割裂**: 知道这是商代鼎,但不知道它在"鼎"这个谱系里位置如何,也不知道跟同期其他器物什么关系
  3. **进阶无门**: 想从"喜欢"升级到"懂行",但中间是悬崖 —— 学术书太枯燥,科普又太浅
  4. **社交错位**: 拍了照片发不出去 —— "这是个鼎"没什么好说的,但深度内容朋友看不懂
  5. **小程序通病**: 现有的故宫/国博 App 是"官方画册",不是"我的图鉴";没有个体化的留存机制

具体的 3 个切面(给 Builder 用)在 `personas-for-builders.md`。

## 2. Value Proposition

> **"让你逛过的每一件国宝,变成你认知地图上一颗会发光的星 —— 维度越填越满,越填越想填。"**

一句更短的:**博物馆爱好者的"图鉴 + 履历 + 鉴宝等级"。**

差异化锚点(vs 故宫数字博物院 / 数字敦煌 / Artsy):
- 我们不是**官方画册的电子版**,我们是**个人收藏履历 + 多维度认知系统**
- 我们不是**百科**,我们是**游戏化的渐进鉴别训练**
- 不堆信息,**让每个维度对应一个值得反复打开的形态**

## 3. Demo 必须出现的 8 个核心页面

每个 Builder (A/B/C) 都要交付以下 8 个 HTML 页面。同一份 mock 数据 (`data/curated/bronze-treasures-v1.json`),不同的呈现哲学。

> 注:night-plan-d0 中 Phase 3 写的是 8 个页面(index, catalog, artifact, time-pillar, ancient-map, pattern-tree, me, scan)。本 PRD 把它们落成可验收的需求。

### 3.1 `index.html` — 首页

**核心使命**: 30 秒内让用户感受到"这不是一个普通博物馆 App",并引导进入 3 大维度入口。

**Must-have**:
- Hero 区:呈现"个人收藏履历"的核心论点(可以是一句标语 + 一个轻量可视化)
- 3 大维度入口卡片(至少 3 个):时空柱 / 古国地图 / 纹路演化树
- 当前用户的收藏状态摘要(已收藏 X 件 / 解锁 Y 个朝代 / 鉴别 Z 类纹饰)—— 即使是 mock,也要让用户**立刻感受到游戏化的存在**
- 入口到图鉴 (catalog)、个人页 (me)、扫一扫 (scan)

**Acceptance**:
- [ ] 不刷新页面,3 大维度入口都点得进去
- [ ] 收藏状态用真实 mock 数据驱动,不是写死的"0/100"
- [ ] 视觉气质要对得起"国宝" —— 不能像电商首页

---

### 3.2 `catalog.html` — 图鉴(三维度切换)

**核心使命**: 让用户能用 3 种维度浏览同一批 20-30 件国宝,体验到"同一件东西在不同维度下意味不同"。

**Must-have**:
- 至少 3 种切换视图:**按时代** / **按出土地** / **按形制**(或者按用途 / 按纹路,Builder 自选,至少 3 种)
- 每个视图都要有**自己的形态**,不能只是"换个排序的列表"(时代 → 时空柱;出土地 → 地图;形制 → 谱系树)
- 已收藏/未收藏要有视觉区分
- 点击任一件 → 跳转 `artifact.html`

**Acceptance**:
- [ ] 3 种维度切换至少 2 个不是"列表+不同排序",而是真的形态各异
- [ ] 国宝级 vs 一级 vs 二级的稀有度有视觉区分(光晕/边框/标识)
- [ ] 至少呈现 15 件文物的完整可视化

---

### 3.3 `artifact.html` — 单件详情

**核心使命**: 一件文物,展示**多个维度的承载形态共存** —— 这是产品创新的浓缩展示位。

**Must-have**:
- 顶部:文物基本信息 + 高清图占位 + 稀有度光晕
- 中部:至少 4 个维度的承载组件并列展示(从 8 个 component-specs 中选):
  - 时代定位(在时空柱上的位置)
  - 出土/馆藏地(在古国地图上的位置)
  - 纹路解读(纹饰可悬停)
  - 用途场景(可视化复原)
  - 工艺工序(简化长卷)
  - 铭文释读(若有铭文)
- 底部:**"加入我的收藏"** 按钮 —— 点击后视觉上反馈"维度填充"
- 相关推荐(同朝代 / 同形制 / 同出土地)

**Acceptance**:
- [ ] 至少 4 个不同维度的承载组件可见且交互正常
- [ ] "加入收藏"动作有明确的游戏化反馈(不是 toast,而是某个维度地图被点亮)
- [ ] 相关推荐至少 3 件,可点击

---

### 3.4 `time-pillar.html` — 时空柱

**核心使命**: 把"时代"这个抽象维度,做成一根**可以填满的柱子**。

**Must-have**:
- 垂直柱状结构:商 → 西周 → 春秋 → 战国 → 秦 → 西汉 → 东汉
- 每个朝代区段标注:时长 / 在你的收藏中的件数 / 该朝代代表器
- 用户已收藏的件数会**填充该区段**,空白区段视觉上有"缺口感"
- 点击某段 → 弹出该朝代的器物列表

**Acceptance**:
- [ ] 区段的填充比例由 mock 数据驱动,有视觉对比
- [ ] 空白朝代有明确的"未解锁"暗示(灰色/虚线/锁图标)
- [ ] 至少 1 处的"诱发收集"文案("还差 2 件解锁'西周通鉴'")

---

### 3.5 `ancient-map.html` — 古国漫游地图

**核心使命**: 把"出土/馆藏地"做成**地图上的漫游足迹**。

**Must-have**:
- 中国地图轮廓(简化即可,SVG)
- 至少 8 个标记点:殷墟(安阳)/ 周原 / 三星堆 / 二里头 / 曾国(随州)/ 越国(浙江)/ 河北 / 西安 / 等
- 已"到访"(=已收藏该地出土件)的标记点亮,未到访灰显
- 鼠标悬停标记:显示该地名 + 该地出土代表器 + 用户已收藏 X/Y

**Acceptance**:
- [ ] 至少 8 个地点,至少 4 个有"已到访"的状态对比
- [ ] 点击标记 → 弹出该地相关文物列表
- [ ] 至少 1 处的"诱发收集"提示("点亮三星堆需收藏 2 件")

---

### 3.6 `pattern-tree.html` — 纹路演化树

**核心使命**: 把"纹饰"这个最专业的维度,做成**树状的渐进解锁体系**。

**Must-have**:
- 树状结构:根节点(青铜纹饰)→ 大类(兽面纹/夔龙纹/凤鸟纹/几何纹/铭文)→ 子类(各种饕餮变体等)
- 已识别的纹饰节点亮起,未识别灰显
- 每个节点可悬停:显示该纹饰的解释 + 出现在哪些器物上
- 进度条:你的"纹饰鉴读等级"(初窥 → 入门 → 熟手 → 鉴读家)

**Acceptance**:
- [ ] 至少 3 层树状结构,至少 12 个纹饰节点
- [ ] 等级进度可视化清晰
- [ ] 至少 1 处"解锁某类纹饰收藏家"称号的暗示

---

### 3.7 `me.html` — 个人图鉴

**核心使命**: 用户的"博物馆履历" —— 这是用户每周回来的核心理由。

**Must-have**:
- 个人头像 + 称号(动态生成,如"西周通鉴入门 / 兽面纹熟手")
- 收藏总览仪表盘:总件数 / 朝代覆盖率 / 出土地覆盖率 / 纹饰鉴读等级
- 最近收藏的 3-5 件(时间线)
- 待解锁成就:再收藏 X 件触发什么称号(至少 3 个进度条)
- 分享按钮(mock 即可)

**Acceptance**:
- [ ] 称号/等级是基于 mock 数据动态计算的,不是写死
- [ ] 至少 3 个"待解锁"成就有明确的下一步引导
- [ ] 视觉上要让人想截屏分享 —— 这是用户增长 hook

---

### 3.8 `scan.html` — 拍照识别

**核心使命**: 让用户感受到"在博物馆现场,拍一张照就能识别 + 加入收藏" —— 即使今晚是 mock。

**Must-have**:
- 摄像头/上传 UI(占位即可,不需要真的调摄像头)
- 选择一张内置 mock 文物图后,**展示识别结果**:文物名 + 朝代 + 馆藏 + 置信度
- 一键"加入我的图鉴"
- "识别为相似器物"的备选 2-3 件(模拟 CLIP 检索结果)

**Acceptance**:
- [ ] 至少 3 张 mock 图可以选,每张返回不同识别结果
- [ ] 置信度数值要看起来"AI 化"(85.3%、92.1% 等,不是固定 100%)
- [ ] "加入收藏"后跳转到 me.html 看到刚加的件

## 4. Validation Criteria(明早 audit 前自检)

每个 Builder 的 demo 在交付时应满足:

### 4.1 完整性
- [ ] 8 个 HTML 页面全部存在,可浏览器打开,不需要 server
- [ ] 至少 6 / 8 个 component-specs 的组件可见
- [ ] 至少 15 件 mock 文物可被浏览到
- [ ] 页面间导航无死路

### 4.2 用户画像清晰度(核心差异化指标)
- [ ] 一个不知道是哪版的人,打开 demo,30 秒内能猜出"这是给哪类用户做的"
- [ ] 视觉、文案、信息密度、交互节奏,都要朝同一个 persona 收敛

### 4.3 维度形态化(产品创新论点)
- [ ] 至少 3 个维度有"专属形态",不是表格 / 下拉 / 文字列表
- [ ] 同一件文物在不同维度下的呈现是不同的(不是数据库视图,是产品视图)

### 4.4 游戏化机制可感
- [ ] 用户能"感受到"为什么要继续收藏(不是"得分+1",而是"地图点亮 / 朝代填充 / 等级提升")
- [ ] 至少 3 处"诱发收集"的文案或视觉(不是教程,而是诱惑)

### 4.5 作品集向度
- [ ] 不像"AI 速涂"的 demo,要看得出有产品思考密度
- [ ] 至少一个画面适合放在简历/案例研究里截图

### 4.6 可 audit 性
- [ ] 6 位 Auditor 在 cold context 下能看懂这是干嘛的(README 或 index 上有简短自我介绍)

## 5. Non-goals(今晚明确不做)

- ❌ **不做真实后端 / API** —— mock JSON 即可
- ❌ **不做真实 AI 识别** —— scan.html 是 mock,真实 CLIP 是 D3 之后
- ❌ **不做小程序原生 (uniapp/Taro)** —— 今晚只交付 HTML demo,小程序化在 MVP 阶段
- ❌ **不做账户系统 / 多用户** —— 单用户 mock state
- ❌ **不做支付 / 商业化** —— 不是 MVP 的一部分
- ❌ **不写完整的 dimensional 内容** —— 20-30 件,每件每个维度信息够 1-2 段即可
- ❌ **不追求完美像素** —— 视觉气质对、交互合理就够
- ❌ **不做多语种** —— 中文为主,英文可选
- ❌ **不做手机端响应式精雕** —— 桌面浏览器优先,移动可看即可
- ❌ **不做无障碍 (a11y) 优化** —— MVP 阶段补
- ❌ **不写测试 / 不做工程化构建** —— 静态 HTML,所见即所得

## 6. 优先级(若时间不足)

P0 — 必交付:
- index / catalog / artifact / me 这 4 个核心页面 + time-pillar 和 ancient-map 两个标志性页面

P1 — 强烈建议:
- pattern-tree(产品创新论点最浓缩的页面)
- scan(AI 化的暗示,作品集向度的关键)

P2 — 可降级:
- 多语种、动效精雕、复杂的 D3 数据可视化

> 三个 Builder 都需要交付 P0 + P1。Builder A/B/C 在 P0/P1 内可有不同的取舍倾向(由 persona 自然决定),但不能跳过任何 P0 页面。

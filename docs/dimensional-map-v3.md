### 1.3 v3 关键升级点(相比 v1)

1. **每张卡片有 "实景照片 ⇄ 线稿剪影" toggle**
   - v1 只有 silhouette (灰色剪影)。v3 每件文物有 1-3 张 CC 实景照片 (来自 `data-schema-v3` 字段 #10), 用户点击 toggle 切换
   - 视觉冲击点: 用户第一次看到"鸮尊"是真照片而非剪影, 立刻被"商人造型力"打到
   - 卡片底部加 `[实景] | [线稿]` 双 chip toggle

2. **尺寸对照条**(v1 完全没有)
   - 同子型(如方尊)4 件按"高度"排成一条横向 bar
   - 用户立刻看到"四羊方尊 58cm 比妇好方斝 32cm 大将近一倍"
   - 数据来源: `size.height_cm` 字段
   - 视觉: 比例严格按真实高度, 不放缩, 让用户身体感觉差异

3. **空位虚线朱砂边 + "?" 剪影 + tooltip 提示**
   - 第 4 格(待补)显示 silhouette + "此位需: 商晚期 · 方尊 · 高度 30-50cm"
   - 点击 → 跳转 catalog filter `?type=方尊&period=商晚期`

4. **"工艺"以小章形式叠加在卡片右下角**
   - 范铸 / 失蜡 / 分铸 / 错金银 等以 12×12 px 小章 (复用印章组件) 叠加
   - 不另设"工艺"维度页面, 把工艺作为形制的属性 surface
   - hover 小章 → tooltip "范铸法 · 28 块陶范分铸"

5. **集齐子型解锁 "进化时间线"**
   - 集齐"方尊"全部已知 4 件 → 解锁"方尊进化"小动画 (商早 → 商晚 → 西周早 三阶段对比)
   - 视觉: 三件并排, 用箭头连接, 标注关键变化("纹饰从满布饕餮 → 局部分散")

### 1.4 跨维度联动

- **形制 × 纹饰**: 点子型(如"方尊") → 在右侧 panel 弹"该子型主流纹饰" (饕餮 65% / 夔龙 40% / 凤鸟 12%) + 纹饰 SVG icon
- **形制 × 时代**: 子型 timeline 自动显示在卡片底部 (商早 ─ 商晚 ─ 西周早), 用户看到一个子型的存活区间
- **形制 × 用途**: 点 ding/gui → 跳到 purpose-scene 中"鼎位 / 簋位"位置高亮

### 1.5 参考范式

- 宝可梦图鉴 (Pokédex) 的"同 Family 比较视图"
- 故宫数字文物库的"按器型浏览"
- Lego Brick Library 的"系列+变体"展示

### 1.6 为什么这种形态承载"形制"的意义

形制不是分类标签, 而是**家族关系 + 比例美学**。v1 的谱系树只画了节点,v3 加入**实景照片 + 尺寸对照**, 让用户的眼睛和身体都参与: 看照片记住器物的"气质", 看尺寸条记住它的"身份感"。集齐解锁进化动画把"收藏"升级为"考据"。

### 2.3 v3 关键升级点(相比 v1)

1. **朝代专属配色**(v1 全部灰底)
   - 夏 `#6e4a2e` (夏褐, 土夯色)
   - 商 `#4a5a3a` (商青铜, 锈青色)
   - 西周 `#a73a2a` (周朱, 朱漆色)
   - 春秋 `#2a2a3a` (春墨, 墨色)
   - 战国 `#7a3a2a` (战赭, 赭土色)
   - 秦 `#1a1a1a` (秦玄, 玄色)
   - 汉 `#b89046` (汉黄, 鎏金色)
   - 配色来自考古学界对各朝代主流器物色调的总结, 让用户**视觉上一眼分辨朝代**

2. **历史事件刻度**(v1 只标了 5 个事件, v3 → 15+ 事件)
   - 必标: 武丁中兴 / 妇好征伐 / 武王伐纣 / 周公东征 / 厉王共和 / 平王东迁 / 三家分晋 / 商鞅变法 / 长平之战 / 统一六国 / 楚汉战争 / 文景之治 / 张骞通西域 / 王莽改制 / 黄巾起义
   - 视觉: 右侧每个事件一个 12px 朱砂圆点 + 横线引到精确年份位置 + label
   - 点事件 → 弹"该年前后 5 件代表器" 小卡

3. **收藏密度叠加 + 颜色饱和度变化**
   - 用户收藏多的朝代段 → 颜色饱和度增加 (从 50% → 100%)
   - 用户收藏空的朝代段 → 灰度 + "呼吸"动效 (CSS keyframe `opacity: 0.4 → 0.7 → 0.4`, 5s loop)
   - 视觉效果: 一眼看出"我在这个时代很活跃, 在那个时代是真空"

4. **缩放下钻**(v1 没有, v3 关键升级)
   - 1× 视图: 7 个大朝代
   - 2× 视图(双指/滚轮放大): 显示子分期 (商早/中/晚 / 西周早/中/晚 / 等)
   - 4× 视图: 显示具体王世 (武丁/武乙/帝乙/帝辛...)
   - 实现: D3 zoom + transform scale
   - 在 4× 视图下, 每个王世可绑定该王世铸主 (周王 → 何尊作器者 → 利簋作器者 等)

5. **"商早期·空白呼吸"作为产品特色**
   - 商早期目前考古发现少, 用户大概率收藏 0 件
   - 这个空白段会持续"呼吸", 文案: "二里岗时期 史料 稀薄, 您 的 收藏 等待 唤醒"
   - 不是负面提醒, 是邀请

### 2.4 跨维度联动 ★

**时代 × 地理 × 纹饰 三维同步联动** (这是 v1 最缺的, v3 必做):

```
   用户 hover "商晚期"
            ▼
   ┌────────────────────────┬────────────────────────┐
   │  时代柱该段高亮         │  地图自动切到商晚期版图   │
   │  ▼                     │   ▼                     │
   │  收藏件浮出 mini cards  │  殷墟 + 三星堆 + 盘龙城  │
   │                        │  同时点亮 (并存文明)     │
   └────────────────────────┴────────────────────────┘
                            ▼
                ┌──────────────────────────┐
                │  纹饰演化树:              │
                │  饕餮纹/夔龙纹 节点闪金光 │
                │  云雷地纹高亮            │
                │  (商晚期主流纹饰)         │
                └──────────────────────────┘
```

实现路径:
- 中央 event bus (`window.dispatchEvent(new CustomEvent('era-changed', { detail: { era: '商晚期', year: -1200 } }))`)
- 各组件 listen 此 event 自动 re-render
- 用户切换"穿越模式"on/off 控制是否触发联动 (默认 on)

### 2.5 参考范式

- Apple Health 睡眠柱(分段视觉)
- Google Earth Engine 时间滑块(时间轴 + 地图联动)
- 史记年表 (年表纵向)
- 《文明 VI》文明时间轴

### 2.6 为什么这种形态承载"时代"的意义

时代不是抽象数字。**朝代专属配色**让"商"和"周"在视觉上立刻分离;**真比例时长**让用户身体感觉到"商有 554 年, 西周只有 275 年";**历史事件刻度**把收藏体验和历史叙事钩在一起;**联动**让用户从"我有几件商代器"变成"我对商晚期这个时代知道了多少"。

### 3.3 v3 关键升级点(相比 v1)

1. **真实地形 GeoJSON**(v1 全是手搓 SVG, 视觉粗糙)
   - 资料源: Natural Earth (CC0) 中国/亚洲地形 + 河流 + 山脉
   - 渲染: D3.js `d3.geoPath()` + `d3.geoMercator()` 投影
   - 底图色调: 暖米色纸张感 (`#f4ebd9`), 山脉用淡墨晕染
   - 大致今行政边界用极淡线条 (1px, 30% opacity) 标示作参照

2. **古国疆域 overlay**(v1 完全没有)
   - 资料源: CHGIS (Harvard China Historical GIS, public access)
   - 5 套 SVG: 商晚期 / 西周早 / 春秋初 / 战国末 / 秦统一
   - 渲染: 半透明虚线边界 + 国名标注 (颜色按朝代专属配色, 见 §2.3)
   - 时代滑块拖动 → CSS transition 平滑过渡 (不是硬切)

3. **双 view (Dual View) 切换**(v1 是两个独立组件)
   - View 1: **出土遗址** (考古发现的古地理) — 地图上是古都/方国遗址
   - View 2: **馆藏分布** (今地理) — 地图上是博物馆位置
   - View 3: **海外流散** (扩展到全球) — 中心从中国移到欧美亚日, 标海外馆
   - 同一个地图组件, URL `?view=excavation|museum|overseas` 切换
   - 视觉一致性: 三个 view 共用同一个朝圣护照 / 集齐机制

4. **每个遗址点的"代表器物图标"**
   - 殷墟 → 鸮尊小 SVG (用 Phase B2 的纹饰 icon 套)
   - 三星堆 → 纵目面具 SVG
   - 周原 → 利簋 SVG
   - 用户点亮该遗址(收藏过其出土器) → 图标从灰色 → 该朝代专属色 + 微动效

5. **海外流散单页**
   - 视觉: 米黄旧纸 + 暗角 + 海风感, 与国内地图视觉区分
   - 每件海外文物配"流亡史" timeline (圆明园流散 / 八国联军 / 抗战转移 / 私人收藏家捐赠)
   - 文案克制("本应在家"作为右下角小注, 不大字煽情)
   - 互动: 用户可"许愿回归" (社交分享 hook, 但只在该 view 出现, 不污染主体)

### 3.4 跨维度联动

- **地理 × 时代** (在 §2.4 已 spec): hover 朝代 → 地图古国边界切换
- **地理 × 形制**: 点遗址 → 该遗址出土器物按形制分类 mini 列表
- **地理 × 铸主**: 点 "曾国" → 自动展开"曾侯乙"档案 + 该国其他铸主

### 3.5 参考范式

- Civilization VI 地图 + 文明边界变化
- Google Earth 时间滑块
- 《史记·世家》风格的"古今对照地图"
- 大英博物馆 Collection Online "Where in the World" 地理探索

### 3.6 为什么这种形态承载"地理"的意义

v1 把出土地和馆藏地分开是错的 — 用户的真实问题是:"这件器物从哪来, 现在在哪, 我要去哪看"。这是一个**前后连续的地理叙事**。v3 dual view 让同一张地图承载"古→今"双时间的对照, 时代滑块让用户**亲眼见证"中国"这个概念在 3000 年里的疆域变化**。海外流散单页是情绪资产, 不是数据陈列。

### 7.4 v3 关键升级点

1. **关系图谱用 D3 force-directed graph** (v1 只画了 ASCII)
   - 节点: 100+ 铸主 (商 20 + 西周 30 + 春秋 20 + 战国 20 + 秦汉 10)
   - 边: 夫妻/父子/君臣/同代

2. **列传卡格式参考《史记·列传》**:
   - 标题: 妇好 (Fu Hao)

### 7.7 为什么这种形态承载"铸主"的意义

青铜器的灵魂不是金属, 是**那个把它铸出来献给祖先的人**。妇好不是名字, 是个有 400+ 件铜器陪葬的女将。把维度做成列传卡 + 关系图谱, 让用户从"我收藏了什么物"变成"我了解了哪些人"。

### 8.5 为什么稀有度做全局层而非独立维度

## 8. 跨维度联动 (Cross-Dimensional Linkages) ★★

> 这是 v1 最薄弱的部分(只在附录写了, 没在 demo 做)。v3 强制 3 组联动落地。

### 8.1 联动 A: 时代 × 地理 × 纹饰 — 三维同步 (v3 必做★)

**触发**: 用户 hover 时代柱某朝代段

**响应**(同时):
1. 时代柱该段高亮 + 弹出 mini cards (用户收藏件 thumb)
2. 地理地图自动平滑过渡到该朝代古国疆域 overlay
3. 纹饰演化树高亮该朝代主流纹饰节点 (商晚→饕餮/夔龙, 西周中→凤鸟, 春秋→蟠螭, 战国→蟠虺)

**实现**:
- 中央 event bus: `window.dispatchEvent(new CustomEvent('era-focus', { detail: { era, year } }))`
- 三组件 listen 此 event 各自 re-render
- 用户可关 ("固定模式" / "联动模式" toggle)

**Hook 强度**: 用户第一次看到"我 hover 一下, 三个组件同时活了" → wow moment

### 8.2 联动 B: 形制 × 纹饰 — "这型主流是什么纹"

**触发**: 用户点形制谱系树某子型 (如"方尊")

**响应**:
- 右侧 panel 弹"该子型主流纹饰" top 5
- 每个纹饰用 SVG icon (来自 §4.3 的 15-25 套) + 出现频次 (例如 "饕餮 65% · 夔龙 40% · 凤鸟 12%")
- 点纹饰 icon → 跳到纹饰演化树该节点 + 高亮含该纹饰的方尊器物

**实现**:
- 数据来源: 每件文物的 `patterns.main / secondary` 字段聚合 (按 `form_subtype` group)
- 实时计算 (不预算)

**Hook 强度**: 用户开始理解"形制不只是形状, 它和纹饰是搭配出现的"

### 8.3 联动 C: 铸主 × 铭文 — "字 → 人 → 物"全链路

**触发**: 用户在铭文释读中 hover 某字(且该字是铸主名)

**响应**:
- 弹该铸主 mini card (列传卡缩略版)
- 显示该铸主的其他传世器 (用户已收藏/未收藏 区分)
- 点"查看完整档案" → 跳铸主页

**实现**:
- 释读字典 `JINWEN_DICT` 加 `caster_ref` 字段 (如"毛公" → `毛公`/`毛伯卫`)
- hover 时 lookup `casters[caster_ref]`

**Hook 强度**: 一个字, 从图像→文字→人物→关联器, 全链打通

### 8.4 其他可选联动 (v4 留坑)

- 用途 × 形制: 场景中点"鼎位" → 弹形制谱系树 鼎 子型 (v3 部分实现)
- 地理 × 铸主: 点曾国遗址 → 弹曾侯乙档案 (v3 部分实现)
- 时代 × 铸主: 时代柱缩放到 4× 显示王世 → 点王世名 → 弹该王作器 (v4 留)

## 9. 给 Visualization Designer 的硬约束 (v3)

1. **每个组件需独立 URL** (`time-pillar.html` / `geo-system.html` / `pattern-tree.html` / 等) — 测试友好, demo 友好
2. **每个组件需显示"用户进度"** — 不只展示信息, 让用户看到自己
3. **稀有度光晕是全局视觉系统** — 渗透每个组件
4. **避免下拉筛选器/复选框多级菜单** — 它们是"信息陈列"反模式
5. **每个组件需有"分享视图"** — 截图友好, 适合用户晒到社交
6. **三组跨维度联动**(§8) 必须有至少 1 组在 demo 中能 trigger
7. **每件 artifact 详情页需展示 11 字段** (见 `data-schema-v3.md`)
8. **mobile 适配留 v4** — v3 只做 desktop

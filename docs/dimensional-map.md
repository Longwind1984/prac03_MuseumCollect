# Dimensional Map — 青铜器 (Chinese Bronzes)

> Domain Researcher 产出 · Phase 1 of Night Run D0
> 这份文档不是"维基百科分类表",而是**把每个维度翻译成可以承载意义的产品形态**。
> Visualization Designer 读完它,应当能直接画出组件草图;Builder 读完 spec 后能直接写代码。
>
> 核心原则: **形态承载意义 (Form carries meaning)** — 一个维度长什么样,决定了用户能不能"感受到"而不只是"看到"它。

---

## 0. 全局视角:为什么是这 10 个维度?

青铜器和瓷器、书画最大的区别: 它是**祭祀政治的物质化**。一件鼎不是审美对象,它是周天子封爵时刻在器底的合同。所以维度拆解必须能映射到三层意义:

1. **时空层** — 它从哪个时代/地点来 (时代、出土地、馆藏地)
2. **器物层** — 它本身是什么 (形制、纹路、用途、工艺、铭文)
3. **价值层** — 它在系统中的等级和故事 (稀有度、铸造者/主人)

10 个维度按这三层组织,每个维度都给出**唯一的产品形态**,不复用。

## 1. 时代 (Dynasty / Period)

### 1.1 子分类
```
夏 (二里头, 约 1750 BC)
  └─ 二里头一/二/三/四期 (青铜萌芽)
商 (1600-1046 BC)
  ├─ 商早期 (二里岗) — 器型初定,纹饰稚拙
  ├─ 商中期 (殷墟一期前) — 过渡
  └─ 商晚期 (殷墟) — 鼎盛,妇好墓黄金期
西周 (1046-771 BC)
  ├─ 西周早期 (武成康昭) — 沿商风,铭文增长
  ├─ 西周中期 (穆恭懿孝) — 列鼎制度成熟,纹饰抽象化
  └─ 西周晚期 (夷厉宣幽) — 长铭文巅峰 (毛公鼎 499 字)
春秋 (771-476 BC)
  ├─ 春秋早期 — 周礼遗存
  └─ 春秋中晚期 — 列国分化 (晋秦楚齐)
战国 (476-221 BC) — 失蜡法、错金银、繁缛
秦汉 (221 BC - 220 AD) — 写实主义、生活化 (长信宫灯/马踏飞燕)
```

### 1.2 推荐产品形态: **垂直时空柱 (Vertical Time-Pillar)**

```
       ┌────────────────────┐
       │ 秦汉 (440 yr)      │ ← 区段高度 ∝ 时长
   ────┤ ░░░░░░░░░░         │
       │ 战国 (255 yr)      │ ← 用户收藏数填充百分比
   ────┤ ████████░░         │
       │ 春秋 (295 yr)      │
   ────┤ ███░░░░░░░         │ ← 暗淡 = 收藏少
       │ 西周 (275 yr)      │
       │   ├─ 早期 ███████░ │ ← 内嵌子分期
       │   ├─ 中期 ████░░░░ │
       │   └─ 晚期 ██░░░░░░ │
   ────┤                    │
       │ 商 (554 yr)        │
       │   ├─ 早期 ░░░░░░░░ │
       │   ├─ 中期 ░░░░░░░░ │ ← 全空 = 0 收藏,诱发感最强
       │   └─ 晚期 ████████ │
   ────┤                    │
       │ 夏 (~250 yr)       │
       │ █░░░░░░░░░         │
       └────────────────────┘
              ▲
       用户手指上下滑动,
       柱体放大缩小,
       点击某段 → 展开该期收藏列表
```

**关键设计**:
- **高度严格 ∝ 朝代时长** (不平均分配),让用户感受"商有 554 年,西周只有 275 年"的时间真实
- **填充率 = 收藏数 / 该期已知国宝数** — 不是绝对数,是百分比,让小朝代不被埋没
- **空白段会"呼吸" (CSS 微动画)** — 空越久越亮的呼吸,逼迫用户去补
- **左侧时间刻度,右侧标注重大事件** (武王伐纣 / 平王东迁 / 三家分晋) — 让收藏的时刻和历史时刻挂钩

### 1.3 参考范式 (灵感非抄)
- Apple Health 的睡眠柱 (柱状但每段语义不同)
- Google Earth 的地质层切片
- 日本"年表柱" (年表縦軸) 的卷轴感

### 1.4 为什么这种形态承载"时代"的意义?
普通 timeline 把朝代画成等长的格子,用户感觉夏=商=西周=春秋,这是**错误的时空体验**。垂直柱按时长真实拉伸,用户滑动时**身体感觉到商的漫长、夏的稀薄、战国的紧凑**。空白段诱发的不是"我要凑数",而是"我对这个时代一无所知"的羞耻感 — 这是博物馆爱好者真正的驱动力。

## 2. 出土地 (Excavation Site)

### 2.1 子分类
按"古国 / 文化区" 而非现代行政区:
```
中原核心区
  ├─ 二里头 (河南偃师) — 夏都?
  ├─ 二里岗 (河南郑州) — 商早期都城
  ├─ 殷墟 (河南安阳) — 商晚期都城
  ├─ 周原 (陕西宝鸡岐山扶风) — 西周王畿
  └─ 丰镐 (陕西西安) — 西周都城
南方青铜文化
  ├─ 盘龙城 (湖北黄陂) — 商早期方国
  ├─ 三星堆 (四川广汉) — 古蜀文明,独立体系
  ├─ 金沙 (四川成都) — 古蜀晚期
  └─ 新干大洋洲 (江西) — 商晚期南方
列国区 (东周)
  ├─ 晋 (山西侯马)
  ├─ 楚 (湖北江陵/河南淅川)
  ├─ 曾 (湖北随州) — 曾侯乙墓
  ├─ 齐 (山东临淄)
  ├─ 秦 (陕西凤翔)
  └─ 越 (浙江绍兴)
其他
  └─ 巴蜀 / 滇 / 中山 (河北平山) / ...
```

### 2.2 推荐产品形态: **古国漫游地图 (Ancient State Wanderer's Map)**

```
        华北平原
   殷墟★═══════
   ┊        ┊         渤海
周原●━━●丰镐         
陕西                 ┊
   ┊      ┊      ┊
   ┊  二里头★    ┊
   ┊   洛阳      曲阜┊
   ┊             鲁┊
   秦             ┊
   ┊             ┊
   ┊             楚┊  曾★
   ┊             ┊  随州
   三星堆★       ┊
   广汉         ●江陵
   ┊            楚都
   ┊                 越●
   ┊                 绍兴

   ★ = 已踏足 (有收藏)
   ● = 未踏足 (空白召唤)
   ┊ = 古国边界 (虚线)
```

**关键设计**:
- **底图是古地图风格,不是现代中国地图** — 用商代/西周/战国分期切换,**山川河流不变,但古国边界在变** (商→周→列国的版图演变本身就是动画)
- **每个遗址点是"足迹徽章"** — 点亮一个遗址,该位置出现一个该遗址代表器物的微型图标 (二里头→爵, 三星堆→纵目面具, 周原→盠驹尊)
- **空白古国会"呼唤"** — 鼠标悬停未点亮区域,显示 "你还没去过 [古蜀],这里出土过 1 件国宝" + 缩略图剪影
- **可切换"个人足迹模式 / 全国宝模式"** — 个人模式只显示自己收藏过的遗址点亮,全宝模式显示所有国宝的分布
- **"穿越"切换按钮** — 把地图时间轴拨到商/周/春秋/战国,边界、国名、点位都会重新排布

### 2.3 参考范式
- 《文明 VI》的探索地图迷雾
- Pokémon Go 的现实地图层
- 《史记·齐世家》风格的古舆图 (毛笔山形 + 虚线疆界)

### 2.4 为什么这种形态承载"出土地"的意义?
"河南安阳"是死的,"殷墟"是活的。古地图模式让用户每次打开都在做一个**穿越行为**: 他不是在看 GPS,他是在看商代地图找鼎。空白古国的"呼唤"机制把"补全收藏"变成"补全足迹",这和单纯的"补全图鉴"在心理上是不同的 — 前者是探险家身份,后者是收集癖。

### 3.2 推荐产品形态: **现实朝圣地图 + 个人收藏护照 (Pilgrimage Map + Passport)**

```
┌───────────────────────────────────┐
│  PASSPORT  甲编  No. 00837        │
│  ─────────────────────────────    │
│                                   │
│  [国博]    ███ 已盖章 4 件         │
│  [上博]    █░░ 已盖章 1 件         │
│  [台北故宫] ░░░ 未踏入             │
│  [大英博物馆] ─── 海外 待启程       │
│  [MET 纽约]   ─── 海外 待启程       │
│  ─────────────────────────────    │
│       ┌─────┐                     │
│       │ 印章 │ ← 用户拍照打卡获得  │
│       └─────┘   特定馆的"虚拟印章"   │
└───────────────────────────────────┘
```

**关键设计**:
- **馆藏维度是 "朝圣维度",不是"信息维度"** — 用户去过 = 真实去博物馆扫描过该件 (或在 app 内确认"我见过")
- **护照 + 印章隐喻** — 每个馆有独特印章图案 (国博 = 鼎纹方印,台北故宫 = 翠玉白菜剪影,大英 = 罗塞塔碑剪影)
- **海外馆藏单独列为"流散篇"** — 视觉上用淡黄色泛旧纸张, 配合 "本应在家" 的小注,触发情感
- **支持"组团朝圣"** — 显示其他用户在同一馆的盖章数,弱社交

### 3.3 参考范式
- 日本国铁车站印章本 (駅スタンプ)
- 集邮册的版式
- 朝圣四国八十八札所的印章本

### 3.4 为什么这种形态承载"馆藏地"的意义?
馆藏地的真正意义不是"它在哪",而是"我得去哪才能见到它"。把维度做成护照,**地理变成行动**,信息变成承诺。流散海外的国宝单独成篇,叙事天然带情绪,无需文案煽情。

## 4. 形制 (Form / Vessel Type)

### 4.1 子分类
按用途大类 → 器型 → 子型:
```
炊器 (烹煮)
  ├─ 鼎 ├─ 圆鼎 (圆腹三足)
  │     ├─ 方鼎 (司母戊/方彝形)
  │     ├─ 扁足鼎 (鸟兽形足,商晚期)
  │     └─ 分裆鼎 (鬲鼎)
  ├─ 鬲 (空足,煮粥)
  └─ 甗 (上甑下鬲,蒸器)
食器
  ├─ 簋 (圆腹圈足,主食)
  ├─ 簠 (长方形,黍稷)
  ├─ 盨 / 敦 / 豆
酒器
  ├─ 爵 (流、柱、三足,饮)
  ├─ 角 (无流双尖,饮)
  ├─ 斝 (圆口三足,温)
  ├─ 觚 (长身侈口,饮)
  ├─ 觯 (扁腹小口,饮)
  ├─ 尊 (盛酒共名)
  │   ├─ 觚形尊
  │   ├─ 方尊 (四羊方尊)
  │   └─ 鸟兽尊 (妇好鸮尊/象尊/牺尊)
  ├─ 卣 (提梁,盛酒)
  ├─ 壶 / 罍 / 瓿 / 觥 / 方彝
水器
  ├─ 盘 (浅腹) / 匜 (有流,洗手) / 鉴 (大盆)
乐器
  ├─ 钟 (悬挂,编钟) / 铙 (倒置敲击) / 镈 / 钲
兵器/工具
  ├─ 剑 / 戈 / 矛 / 钺 / 车马器 / 度量衡
```

### 4.2 推荐产品形态: **形制谱系树 + 同型号对照墙 (Form Genealogy Tree + Comparative Wall)**

```
         [酒器]                  ← 根节点
            │
   ┌───┬───┼───┬────┬───┐
   尊  卣  壶 觚  斝  爵...
   │
   ├─ 觚形尊
   ├─ 觯形尊
   ├─ 方尊 ─────┐
   │           ▼
   │     ┌────────────┐
   │     │   方尊墙    │ ← 点击 "方尊" 进入
   │     │ ┌─┬─┬─┬─┐ │   同型号对照墙
   │     │ │四│妇│牺│龙│ │   (类似 Pokédex)
   │     │ │羊│好│尊│尊│ │
   │     │ │方│方│ │ │ │
   │     │ │尊│尊│ │ │ │
   │     │ └─┴─┴─┴─┘ │
   │     └────────────┘
   └─ 鸟兽尊
      ├─ 鸮尊 (妇好)
      ├─ 象尊
      ├─ 牺尊
      └─ ...
```

**关键设计**:
- **谱系树是开放式的,不固定节点** — 用户收藏一件新形制 → 树上出现一个新分支,带"新发现"光效
- **同型号对照墙是 Pokédex 式** — 一个子型 (如"方尊")下,所有已知国宝排成一排,空位是剪影 + ? 号
- **集齐一支可解锁"特殊视图"** — 比如集齐 6 件"鸮尊" → 解锁"鸮尊的进化时间线" (附带原始展品 360 模型对比)
- **每个器型有"度量条"** — 用户可以横向比较该型号的尺寸/重量分布 (后母戊鼎 832kg vs 子龙鼎 230kg 一目了然)

### 4.3 参考范式
- Pokédex 图鉴的子型展示
- 生物分类树 (但更扁平,不要 7 层)
- 乐高编号本

### 4.4 为什么这种形态承载"形制"的意义?
形制不是"标签",是**家族关系**。把同型号文物并排展示,用户立刻看出"原来妇好鸮尊和后世猫头鹰造型有关",这种**相似性的视觉冲击**是单件浏览给不了的。集齐解锁"进化时间线"则把"收藏"变成了一种学术行为 — 用户在做对照研究。

## 5. 纹路 (Patterns / Motifs)

### 5.1 子分类
按主题 + 演变:
```
神兽纹 (商晚期-西周早期,神权)
  ├─ 饕餮纹 (兽面纹) — 大类,主流
  │   ├─ 单元饕餮 (整面)
  │   ├─ 分解饕餮 (中线展开)
  │   └─ 顾首饕餮 (回头形)
  ├─ 夔龙纹 (单足侧视龙)
  ├─ 夔凤纹
  ├─ 蟠螭纹 (春秋战国流行)
  └─ 鸱鸮纹

写实动物纹
  ├─ 鸟纹 (凤鸟纹,西周中期主纹)
  ├─ 鱼纹 / 龟纹 / 蝉纹 / 虎纹 / 象纹

几何纹 (西周中晚期-春秋,王权抽象化)
  ├─ 窃曲纹 (夔龙抽象化)
  ├─ 重环纹
  ├─ 鳞纹
  ├─ 波曲纹
  └─ 蟠虺纹

底纹 (背景)
  ├─ 云雷纹 — 几乎所有商周器物的"画底"
  └─ 弦纹

人物/场景纹 (战国汉)
  └─ 宴乐攻战纹 / 狩猎纹 / 采桑纹
```

### 5.2 推荐产品形态: **纹路演化树 + 纹饰拓片放大镜 (Pattern Evolution Tree + Rubbing Loupe)**

```
                       ┌─────────────┐
                       │  夔龙纹     │ 商晚期
                       │   〰️        │
                       └──────┬──────┘
                              │
              ┌───────────────┼──────────────┐
              ▼               ▼              ▼
        ┌──────────┐   ┌──────────┐    ┌──────────┐
        │ 顾首夔龙 │   │ 双身夔龙 │    │  抽象化   │
        │ (西周早) │   │ (西周中) │    │           │
        └─────┬────┘   └──────────┘    └────┬─────┘
              │                              │
              ▼                              ▼
        ┌──────────┐                   ┌──────────┐
        │ 窃曲纹    │ ← 由夔龙演化     │ 重环纹    │
        │ (西周晚) │                   │ (春秋早) │
        └──────────┘                   └──────────┘

  每条分支需用户"识别 / 收藏带此纹饰的器物"才会点亮.
  分支末梢未点亮 = 灰色虚线 + ? 号.

  ┌─────── 放大镜模式 ──────┐
  │ 用户对器物图拖拽框选纹饰 │
  │ → 系统识别 "这是窃曲纹"  │
  │ → 在演化树上点亮对应节点 │
  └────────────────────────┘
```

**关键设计**:
- **演化树有真实的考古学传承关系**,不是任意分类 — 这是这个组件最难也最值钱的点
- **拓片放大镜** — 用户对一件器物长按,可"拓"下一片纹饰 (黑白拓片风格)。拓片可独立收藏,形成"纹饰拓本集"
- **解锁称号** — 集齐某分支所有节点 → 获得 "凤鸟收藏家 / 饕餮鉴定师 / 窃曲修士" 等称号 (称号挂载在用户头像旁)
- **跨器物纹饰对照** — 用户点击树上某节点 → 跳出"所有收藏的此纹饰器物" 平铺墙,可对比同纹饰在不同器物上的应用

### 5.3 参考范式
- 技能树 (Skyrim / Path of Exile)
- 中医穴位图 (节点 + 经络)
- 字体演变图 (甲骨→金→篆→隶→楷)

### 5.4 为什么这种形态承载"纹路"的意义?
纹路不是装饰,是**思想的视觉编码**。饕餮→窃曲是"神权→礼制"的视觉化转变。演化树让用户在收藏的过程中,**亲眼见证抽象化进程**。这比任何文字说明都更有冲击力。拓片放大镜则让用户的眼睛被训练 — 他开始能区分夔龙和蟠螭,这种"鉴别能力的获得"本身就是产品的核心回报。

## 8. 铭文 (Inscription / Jin Wen)

### 8.1 子分类
按字数 + 内容:
```
按字数等级
  ├─ 微铭 (1-5 字) — 族徽/日名,商早中期
  ├─ 短铭 (6-20 字) — 商晚期-西周早期
  ├─ 中铭 (21-100 字) — 西周中期主流
  ├─ 长铭 (101-300 字) — 西周晚期巅峰
  └─ 史诗铭 (300+ 字) — 毛公鼎 499/史墙盘 284

按内容类型
  ├─ 族徽 / 日名 (商,亚某 / 父乙)
  ├─ 册命 (周王封赏)
  ├─ 战功
  ├─ 婚配
  ├─ 诉讼
  ├─ 祭祀 (作器为祖某)
  └─ 律令 (商鞅方升)
```

### 8.2 推荐产品形态: **铭文释读器 — 字字悬停翻译 + 铭文段位 (Inscription Reader + Reading Rank)**

```
   ┌──────────────────────────────────────┐
   │   毛公鼎铭 (西周晚期,499 字)         │
   │   ───────────────────────────────    │
   │                                       │
   │   王 若 曰 父[歆] 不[显] 文 武        │
   │   ▲   ▼                               │
   │   悬停 "若" 字 ↓                      │
   │   ┌───────────────────────┐          │
   │   │  若 ruò                │          │
   │   │  金文释: 顺从,如此     │          │
   │   │  甲骨原形: 𠰷         │          │
   │   │  本铭中: 这样说道       │          │
   │   │  你已识别此字: 第 4 次  │          │
   │   └───────────────────────┘          │
   │                                       │
   │   ▼ 拓片视图 / 释文视图 / 白话视图    │
   │                                       │
   │   ───────────────────────────────    │
   │   段位: 「金文识读·二段」             │
   │   累计识字: 187 / 已知金文 3700        │
   └──────────────────────────────────────┘
```

**关键设计**:
- **三层视图切换**: 拓片 (黑白原貌) / 释文 (现代汉字) / 白话 (大意翻译)
- **字字悬停翻译** — 每个字独立可点,显示金文原字 + 现代字 + 含义。**核心是:每次识字都记入用户档案**
- **段位系统** — 累计识字数 → 入门/一段/二段/.../鉴师/大宗师 段位
- **铭文成就墙** — 你已识读的国宝铭文列表,毛公鼎 499 字读完即可获得"毛公鼎释读完毕"成就 (这是个高难度长期目标)
- **铭文之间的字关联** — "若"字在毛公鼎和大盂鼎都出现 → 显示"你在 3 件器上见过此字" → 形成字的跨器物轨迹

### 8.3 参考范式
- LingQ / 多邻国的悬停翻译
- 文言文学习 App 的"古今对照"
- 围棋段位制 (识字数 → 段位)

### 8.4 为什么这种形态承载"铭文"的意义?
铭文是青铜器最被低估的维度 —— 普通用户看一眼"哦有字",就翻过去了。释读器让铭文从"图像"变成"可读文本",再变成"可学习语言"。**段位制把铭文识读做成了一个长期的学习曲线**,让重度用户有持续动机。这是产品里最"深"的一个维度,专门服务硬核爱好者。

### 9.1 子分类
按官方定级 + 非官方语义:
```

  ├─ 一级文物 (其中孤品/易损品禁止出境)
  ├─ 二级文物
  └─ 三级文物

  ├─ 出土地稀有 (如三星堆器物因独立文明而稀有)
  └─ 流散海外
```

### 9.2 推荐产品形态: **稀有度光晕 + 收藏卡光效系统 (Rarity Halo + Collection Card FX)**

```

   ┌─────────┐

   └─────────┘

   │   ✦──◆──✦     │
```

- **不是用"星级"做稀有度,用"光晕 + 印章"** — 因为青铜器的稀有感来自"国之重器"的传统视觉语言,不是游戏化星星

- **稀有度面板** — 个人收藏中按稀有度分布的雷达图: "你的国宝率 14%,行业平均 4%"
- **稀有度光晕作用于所有视图** — 不只是卡片,在时空柱、地图、形制谱系所有地方,国宝都以光晕区分

- 故宫文创的"国宝"系列视觉

稀有度的核心是"我手里这件配得上什么样的礼遇"。**用光晕 + 印章而非星级**,是为了让稀有感植根于传统文物语言而非游戏语言 —— 这是博物馆爱好者的硬核分界线。当用户拿出后母戊鼎收藏卡,旁边那枚"国之重器"红章会让他感觉"我在手藏国家的脸"。

## 11. 维度组合 (Dimension Combinations)

至少 2 个跨维度组合的协同,放在 motivation-hooks.md §3 详述,这里先列出钩子:

### 组合 A: 时代 × 出土地 — **古国时空叠加**
垂直时空柱左侧 + 古国漫游地图右侧联动。点击时空柱"商晚期" → 地图自动跳转到商晚期版图,殷墟和三星堆同时点亮 (并列存在的两个文明)。
→ 详 motivation-hooks.md §3.1

### 组合 B: 形制 × 用途 — **礼制完整性引擎**
形制谱系树和场景重建场景双向绑定。用户在场景中放入一件方鼎,谱系树同步点亮该子型。集齐九鼎 (在场景中归位) → 解锁"天子之礼"特殊视图。
→ 详 motivation-hooks.md §3.2

### 组合 C: 纹路 × 时代 — **纹饰史观**
纹路演化树的横轴和时空柱垂直锁定 — 用户看夔龙纹时,树上对应时代会高亮,反之亦然。

## 附录 B: 给 Visualization Designer 的硬性约束

1. **每个组件都需可独立运行** (URL 直达,无侧栏依赖)
2. **每个组件都必须显示 "用户进度"** (不只展示信息,要让用户看到自己)
3. **稀有度光晕是全局视觉系统**,不是单独组件 — 它叠加在每个组件上
4. **避免下拉筛选器 / 复选框 / 多级菜单** — 这些是"信息陈列"的典型反模式
5. **每个组件需有"分享视图"** — 截图友好,适合用户晒到社交

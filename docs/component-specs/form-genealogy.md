# Form-Genealogy — 形制维度 (形制谱系树 + 同型对照墙)

## One-line purpose
把"形制"从"商鼎"这种孤立标签,翻译成**家族关系的可视化** — 用户在一张谱系树上看见"鼎"这个形制是怎么从二里头到秦汉一路变形的,然后在"方尊墙"上看见 4 件方尊并排站好,集齐就解锁该子型的"进化时间线"。

## Visual description

**两层结构**:
1. **谱系树 (Tree)** — 横向卷轴式生物分类树,根节点 = "青铜礼器全谱",二级节点 = 大类(炊器 / 食器 / 酒器 / 水器 / 乐器 / 兵器),三级 = 器型(鼎 / 簋 / 尊 / 爵...),四级 = 子型(方鼎 / 圆鼎 / 扁足鼎...)。每个节点是一个**毛笔速写器型图标**,不是文字。
2. **同型对照墙 (Wall)** — 点击某个四级子型节点 → 全屏切换到 Pokédex 风格的对照墙,显示该子型所有已知件物并排,空位是剪影 + ? 号。

**关键视觉细节**:
- 谱系树是**横向滚动**(从根到叶左→右),不是垂直的(垂直会和时空柱混淆)
- 树的连线是**毛笔风格**(SVG path stroke="brush"),不是工程化直角线
- 每个节点的器型图标是**剪影线描**,已收藏件类型显**深色铜绿**,未收藏显**淡灰虚线**
- 国宝级子型节点周围有**金色微光晕**(见 `rarity-halo.md`)
- 对照墙的剪影空位是**做旧问号 + 子型属性提示**("商晚期·方鼎·待补")

## Interaction behavior

- **默认状态**: 谱系树视图,根节点居左,展开到三级(器型),四级折叠
- **Hover 节点**: 节点放大 + 浮出气泡 "鼎 · 食器主器 · 你已收藏 8/27"
- **Click 节点**: 该节点展开下一级;若已是四级 → 切到对照墙
- **Drag 树**: 在视口内平移,鼠标 wheel 缩放
- **Click 对照墙剪影**: 弹出"该位需要的属性" — "此位需西周早期·方鼎·尺寸 < 50cm · 出土地推测中原",并提示"以下 3 件可能符合 → 跳查"
- **Long-press 已收藏件物卡**: 弹"加入对比" — 选 2-3 件进入并排对比视图(度量条 + 纹饰列表 + 铭文字数对比)
- **集齐子型动效**: 集满 X 件 → 该子型节点变金色 + "进化时间线"按钮浮出 → 点击进入按时代排列的子型时间线视图
- **Transitions**: 节点展开是"卷轴展开"效果(width auto-grow 300ms);剪影→实物的填充是渐变溶解 600ms

## Data requirements

**Required fields from `bronze-treasures-v1.json`**:
- `type`(炊器/食器/酒器/水器/乐器/兵器)
- `form_subtype`(具体子型,如"方鼎""鸮形尊""莲鹤方壶")
- `size.{height,weight,length}_cm`(用于尺度比较条)
- `dynasty` + `period`(用于进化时间线)
- `rarity_level`、`id`、`name_zh`

**Derived data**:
- `genealogy_tree[]` — 一份手工 curated 的器型分类树(Designer + Researcher 提供约 50 节点)
- `subtype_pool{subtype: [ids]}` — 每个子型已知件物池
- `subtype_collected{subtype: [collected_ids]}` — 用户收藏
- `subtype_complete_threshold{subtype: count}` — 集齐阈值(通常 = pool size)

**User state**:`user.collected_ids[]`,`user.unlocked_evolution_views[subtype]`(已解锁的进化时间线列表)

## Game mechanic hook

- **集齐 = 学术揭示,不是 XP**: 集齐"方尊"4 件 → 解锁的不是"+1000 经验",是一个**真正有价值的视图**(方尊从商到西周的演化对比,带文字解读)
- **空位剪影 + 提示属性**: "此位待补" 不是空白,是带"形制+时代+尺寸"的剪影,精确诱发用户去搜
- **"罕见子型"标签**: 龙形觥 / 鸮形尊 等极少见子型自动带"孤型"小印章,稀缺感强
- **跨子型对比**: 多个鼎并排时,**尺度比较条**让"后母戊鼎 832kg vs 子龙鼎 230kg" 数字第一次具象化,这是单件页面给不了的快感
- **称号系统**: 集齐"鼎"全部子型 = "鼎类大师";集齐"酒器"大类全部 = "尊觚爵斝皆通"

## Implementation hint

- **Tech**: D3.js tree layout(`d3.tree()` 或 `d3.hierarchy()`)+ SVG;对照墙用 CSS grid + framer-motion
- **Approximate complexity**: moderate-hard(谱系树数据结构需要 hand-curated)
- **Libraries**: D3.js 是核心,framer-motion 做节点入场/对照墙转场,Tailwind 用于面板
- **Mobile considerations**: 树视图在移动端改为**纵向 drilldown**(点节点 → 进入子层,面包屑导航);对照墙在移动端 2 列 grid,单卡可全屏放大

## Cross-component connection

1. **形制 × 用途(组合 B)**: 与 `purpose-scene.md` 双向绑定 — 用户在场景中拖入一件方鼎 → 谱系树该子型同步点亮;在谱系树点击空白节点 → 场景中对应礼器位置高亮。详 motivation-hooks.md §3.2。
2. **稀有度光晕**: 国宝级子型节点金边,孤型子型(龙形觥等)有"孤"小印
3. **铸造者档案**: 对照墙某件物可链接到 `caster-profile.md`(如妇好系列的鸮尊→妇好档案)
4. **铭文**:对照墙的件物卡上小角标显示铭文字数(让"长铭"作为额外维度自动可见)

## Persona differentiation

- **A 考据派**: 谱系树根据《商周青铜器分期标准器》风格,带断代标尺(在子型旁标"标准器: 后母戊鼎 K9999");可切换"按容量分类 / 按造型分类 / 按用途分类"三套谱系视图;每个节点有"参考文献"小图标点开看引用;支持"导出此分支"为 markdown 表格
- **B 沉浸派**: 树的视觉是**毛笔水墨手绘**,节点是有笔触感的剪影;对照墙的件物排列有"博物馆展柜"感(打光、阴影、玻璃反光占位);每解锁一个进化时间线,弹出一段叙事文案"鼎,从二里头的拙朴到秦的雄浑,3000 年里它学会了什么"
- **C 探索派**: 谱系树支持"宝可梦图鉴模式" — 每个子型是一张卡牌排在 grid 里,可点击翻面;集齐子型有金光爆炸 + 称号弹出动效;每件卡可一键生成"我的鼎类图鉴 8/27" 分享卡;有"我的稀有子型" 排行(本地)

## Don't do these

1. **不要做成"维基百科分类层级树"**— 节点要有视觉(剪影),不只是文字
2. **不要让对照墙变成"商品列表"**— 它是 Pokédex,每个位置都是有意义的(代表一件可能存在的国宝),不能是无序卡牌
3. **不要给"集齐"奖励无价值的徽章**— 解锁内容必须本身有价值(进化时间线、对比视图),否则就是 XP 农场

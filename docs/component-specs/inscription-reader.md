# Inscription-Reader — 铭文维度 (字字悬停释读器 + 段位制)

## One-line purpose
把"铭文"从"图像"变成"可读文本",再变成"可学习语言" — 用户每识一字累入档案,段位从"入门"到"金文大宗师"。这是产品最深的长尾 hook,服务硬核爱好者,但同时是 day-1 用户能尝鲜的"哦原来这是字"的 wow 来源。

**关键视觉细节**:
- 拓片层用**做旧黑白宣纸**质感,字字独立可点
- 释文用**衬线体或楷书**,字间距宽,方便点击
- 白话译文用**思源宋体**,字号略小
- 段位印章压在用户头像旁,印章实体逐级升级,**字体由古到今**(铜青色印 → 碧玉印 → 金印)
- 未识字显示**问号代替**(用户没点过的字默认不显释文)
- 国宝级铭文(毛公鼎 499 字、大盂鼎 291 字、史墙盘 284 字)有"史诗铭"金标

## Interaction behavior

- **默认状态**: 拓片 + 释文双栏显示,所有字均显释文(用户已识字标深色,未识字浅灰)
- **Hover 字**: 弹出该字的**释字卡** — 金文原形 + 拼音 + 字义 + 本铭中含义 + "你已识 X 次,在 Y 件器中"
- **Click 字**: "识字 +1"(若该字尚未点过)动画,该字在拓片层泛淡金光,段位累计器 +1;弹出该字的"跨器轨迹" — 显示该字出现在用户已收藏的哪些器物的哪些位置
- **Double-click 字**: 跳到"金文字典"该字详情页(可选扩展)
- **顶部切换 视图**: 拓片+释文 / 拓片+白话 / 三栏 / 单纯拓片(给硬核用户做盲读训练)
- **进度条 hover**: 显示该铭可识字数 / 总字数
- **段位升级动画**: 当累计字数跨过阈值,顶部弹出**克制的升段动画**(印章实体放大,旧印淡出,新印盖上,1.5 秒,带篆刻"叩"音占位)— 不是花哨的彩带

## Data requirements

**Required fields from `bronze-treasures-v1.json`**:
- `inscription.has` (bool)
- `inscription.char_count` (字数)
- `inscription.text` (实际铭文,若有)
- `inscription.summary` (铭文背景)
- `id`、`name_zh`

**Derived data**:
- `inscription_corpus[]` — 一份 hand-curated 的金文字字典(约 200-300 字),每字含:金文原形、楷化字、拼音、字义、本铭中含义、出现器物列表
- `inscription_dict_per_artifact{artifact_id: [{char, position, char_data}]}` — 每件铭文器逐字数据
- `total_known_jinwen` ≈ 3700(常用已释金文,作为段位长期目标的"分母")

**User state**:
- `user.recognized_chars[]` — 用户已识字列表(去重,每个字记录首次识字日期 + 来源器物)
- `user.recognized_char_count` = 累计识字总数
- `user.inscription_rank` = "入门 / 一段 / .../ 大宗师" 段位
- `user.completed_inscriptions[]` — 已通读完成的铭文器物列表

## Game mechanic hook

- **Identity hook ★★ (最强)**: 段位制是产品最深的身份系统,服务硬核用户的长尾留存。段位印章 + 字数,是用户能炫耀的"知识资本"
- **Completion hook**: 单铭"通读"是高难度长期目标 — 毛公鼎 499 字读完可能要几个月,但每次打开看到进度增长就有动机
- **Connection hook**: 字字跨器关联("若" 字出现在 7 件器) — 用户的字典扩展到第三层(字 → 铭 → 器 → 时代);自动形成"字的轨迹"地图
- **Story hook**: 长铭文是一篇文章,通读后整段历史豁然 — 毛公鼎 = 周宣王训诫;大盂鼎 = 康王告诫"酒戒商鉴";散氏盘 = 中国最早的土地契约
- **稀有标签**: 史诗铭(300+ 字)国宝级有"史诗铭" 金标;何尊 "宅兹中国" 4 字有专属"中国" 印章
- **跨铭学习曲线**: 用户在毛公鼎学到的字,在大盂鼎复用 → 第二件读起来比第一件轻松,这种"会越来越容易" 的体验是核心动机

## Implementation hint

- **Tech**: HTML 文本 + 每字 `<span>` 包裹,hover/click 用 vanilla JS 事件;拓片用图片或 SVG 显示;段位印章用 SVG inline
- **Approximate complexity**: hard(数据 curation 巨大:200+ 字 × 多个属性,工程实现 moderate)
- **Libraries**: 不需要重型库;framer-motion 用于升段动画;Tailwind 用于面板
- **Mobile considerations**: 移动端字间距更宽(touch target ≥ 44x44px);释字卡用底部抽屉而非 hover 浮窗;跨器轨迹用横向卡片滑动

## Cross-component connection

1. **铭文 × 铸造者(组合 D)**: 与 `caster-profile.md` 联动 — 用户识"毛公" 二字 → 自动跳铸主档案;识"妇好" → 跳妇好档案。详 motivation-hooks.md §3.4。
2. **稀有度光晕**: 史诗铭(300+ 字)金边 + "国之重器" 印
3. **时代联动**: 不同时代的金文字体不同,字字卡片显示该字的"时代风格"标签(商体 / 西周早 / 西周晚...)
4. **纹路联动**: 字也可视为纹饰的一种(铭文与纹饰共存),拓片放大镜识别可同时识别纹饰和字

## Persona differentiation

- **A 考据派 ★(这是 Builder A 最深的杀手锏组件)**: 字字卡片包含**异体字(《集成》编号)、字源(甲骨→金文→篆→楷四段演变图)、学界争议**(如"后母戊"vs"司母戊"的释读争议);支持"批注模式" — 用户可在每字旁加私人笔记;支持导出整篇铭释文为 markdown 或 LaTeX(用 CJK 包+ 金文字符);跨器轨迹支持引用导出
- **B 沉浸派**: 字字卡片有**音频朗诵占位**(古汉语模拟 + 现代汉语双轨);释字动画有"墨色晕开" 效果;段位升级有**山水卷轴展开 + 古琴音**;通读一篇长铭后弹出叙事文案"你今天读完了 3000 年前周宣王对叔父的训诫"
- **C 探索派**: 段位印章可炫耀(挂头像),升段有"叮叮叮"特效;"今日金文挑战"小游戏(5 字闪现识别)给短期 day-1 抓手;字字识可分享"我识了 187 字"卡片;有"我比朋友识字多 30%" 比对(本地 mock)

## Don't do these

1. **不要把段位做成数字等级 (Lv.1 Lv.99)** — 段位用篆刻印章 + 段位词(入门/一段/.../大宗师),根植于围棋传统而非游戏 UI
2. **不要把"识字 +1"做成数字弹窗** — 数字+1是 XP 农场的感觉,正确做法是"该字在拓片中泛金光 + 段位累计器悄悄涨"
3. **不要把白话译文做得过度文学化** — 白话是辅助理解,不是文学创作;过度文学会误导原意
4. **不要让段位升级"中断用户体验"** — 升段动画必须可跳过、< 2 秒,不能像传统游戏那样强制全屏庆祝

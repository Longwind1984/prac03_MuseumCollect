# Caster-Profile — 铸主/主人维度 (铸主档案卡 + 关系图谱)

## One-line purpose
青铜器的灵魂不是金属,是**那个把它铸出来献给祖先的人**。把"铸主"维度做成名片式档案 + 关系网络图,让用户从"我收藏了什么"升级到"我了解了谁"。妇好不是名字,是有 400 多件铜器陪葬的女统帅。

## Visual description

**两层结构**:
1. **铸主档案卡** — 单人详情页,像《刺客信条》历史人物档案 + 维基百科信息盒
2. **铸主关系图谱** — 网络图,所有有铭文铸主互相之间的政治/家族/君臣关系

**关键视觉细节**:
- 档案卡风格: **米黄做旧 + 朱砂印章 + 篆书/楷书 + 简笔头像剪影**,接近清代名臣画传
- 头像不是真实复原(避免胡乱想象),而是**毛笔速写剪影 + 器物代表符号**(妇好 = 鸮 + 戈;武丁 = 鼎 + 卜骨;曾侯乙 = 编钟剪影)
- 关系图谱采用**家谱/族谱风格**,而非游戏化关系网;节点是圆形玉璧形,连线是毛笔线
- 国宝级铸主(妇好、武丁、周宣王、曾侯乙)节点带金边

## Interaction behavior

- **默认状态**: 用户进入页面默认看的是"我已涉及的铸主"列表(以收藏件数排序)
- **Hover 节点(关系图)**: 浮出该铸主的"含 X 件已知作品 / 你已收藏 Y 件"小卡
- **Click 节点**: 跳转该铸主档案卡
- **Click 档案卡的关联国宝**: 跳器物详情页
- **Click 档案卡的人物关系**: 跳关系图谱,该铸主在网络中央高亮
- **Drag 关系图**: 节点可拖动重排;Wheel zoom
- **Long-press 档案卡**: "导出为分享卡片"(B 沉浸派的钩子)
- **Transitions**: 档案卡入场是"翻牌"效果(CSS perspective + rotateY,600ms);关系图节点间连线有渐进画出动效

## Data requirements

**Required fields from `bronze-treasures-v1.json`**:
- `inscription.text` 和 `inscription.summary`(用于解析铸主名)— 关键字段
- `dynasty`、`period`
- `id`、`name_zh`、`current_museum`
- `excavation_site`(妇好系都出自殷墟妇好墓,可作辅助识别)

**Derived data**:
- `caster_index{caster_name: [artifact_ids]}` — 一份手工 curated 的铸主-器物索引(由 Researcher 提供),约 15-20 个铸主
- `caster_meta{caster: {role, era, gravesite, story, image_silhouette}}` — 每个铸主的元数据
- `caster_relations[]` — 铸主之间的关系边(夫妻/父子/君臣/同朝),约 20-30 条边
- 主要铸主清单(基于 bronze-treasures-v1.json):
  - **妇好**(鸮尊、司母辛鼎、觥...)
  - **妇妌(后母戊)**(后母戊鼎)
  - **周成王 + 何(器主)**(何尊)
  - **周康王 + 盂**(大盂鼎)
  - **周孝王 + 膳夫克**(大克鼎)
  - **周宣王 + 毛公**(毛公鼎)
  - **周宣王 + 虢季子白**(虢季子白盘)
  - **西周散国/矢国君主**(散氏盘)
  - **武王 + 利(将领)**(利簋)
  - **越王勾践**(越王勾践剑)
  - **曾侯乙**(曾侯乙编钟、尊盘)
  - **商鞅**(商鞅方升)
  - **秦始皇**(铜车马,虽无铭但有戳印)
  - **(其他)**: 三星堆铸主无名;后母戊鼎主是商王祖庚

**User state**:
- `user.unlocked_casters[]` — 用户涉及的铸主列表(基于已收藏件物自动推导)
- `user.caster_completion{caster: x/y}` — 每个铸主下的完成度

## Game mechanic hook

- **Story hook ★**: 每位铸主背后的历史人物故事是核心钩 — 妇好的女将军生涯;曾侯乙的乐工组合;商鞅变法到秦统一;周宣王中兴...
- **Completion hook**: "妇好 12 件全集" 是高难度长期目标(年级反馈)
- **Connection hook**: 铸主关系图把"器物收藏"延伸到"人物收藏" — 这是从"物"到"人"的升级
- **Identity hook**: "妇好系列收藏家 / 周宣王作器人 / 曾侯乙乐工" 等称号
- **特殊跨维度组合(组合 D,见 motivation-hooks §3.4)**: 用户在铭文释读器里识"毛公" 二字 → 自动跳铸主档案 → 用户瞬间从"读字"被引到"了解人"

## Implementation hint

- **Tech**: 档案卡用 HTML + CSS(做旧米黄底 + SVG 头像);关系图用 D3.js force layout 或 cytoscape.js(节点 + 边)
- **Approximate complexity**: moderate-hard(数据 curation 是工作量,UI 实现 moderate)
- **Libraries**: D3.js force / cytoscape.js;framer-motion 用于档案卡翻牌
- **Mobile considerations**: 关系图在移动端**改为列表 + tag 视图**(节点变 chip,关系变 tag);档案卡保持单页

## Cross-component connection

1. **铭文 × 铸造者(组合 D)**: 与 `inscription-reader.md` 双向 — 用户在铭文中识到铸主名字 → 自动跳档案;在档案卡可跳回该铸主作品的铭文释读。详 motivation-hooks.md §3.4。
2. **稀有度光晕**: 国宝级铸主(妇好、曾侯乙)档案卡金边
3. **场景重建**: 集齐妇好系列 → 解锁"妇好祭祀场景"(殷王武丁王后专属);集齐曾侯乙乐器 → 解锁"曾侯乙乐工场"
4. **形制 + 出土地**: 妇好墓的件物(殷墟出土)在地图和谱系中可"按铸主聚合"高亮

## Persona differentiation

- **A 考据派 ★(这是 A 的二级杀手锏)**: 档案卡字段更深 — 出土报告引用、铭文释读争议(如"后母戊"vs"司母戊"的女主释读分歧)、断代依据;支持"我的研究笔记"挂载在每位铸主页;关系图可切换"考古证据驱动 / 推测驱动" 两套关系网;支持导出整位铸主的器物对比为 LaTeX 表格
- **B 沉浸派**: 档案卡是**人物长卷**(可竖向滚动看完整生平);头像剪影有水墨晕染感;生平叙事用文学化文案"妇好,你死于公元前 1200 年的某个清晨。三千年后人们打开你的墓,看到 468 件你的铜器还在,沉默地等你回来";有"国宝独白"音频占位(妇好的旁白)
- **C 探索派**: 档案卡像"角色卡牌"(《原神》角色界面感)— 头像、技能(指铸过的器物)、稀有度;关系图谱有"羁绊"机制(集齐家族成员有奖励);可生成"我的妇好图鉴 3/12" 分享卡;有"今日推荐铸主"卡牌抽取

## Don't do these

1. **不要乱给历史人物画"复原图"**— 头像必须是毛笔速写剪影,绝不能是 AI 生成的"妇好真实容貌"等胡乱想象,会让 A 考据派立刻删 App
2. **不要把关系图做成纯游戏式技能树**— 它是"族谱 + 政治网络",视觉根植于家谱传统而非《刺客信条》技能树
3. **不要在生平叙事里加情感倾向性强的政治判断**— 历史争议有的,但写法应中性(如商鞅变法的功过可以提两派观点,不要单边)
4. **不要把"集齐 X 系"做成主要 KPI**— 这容易让用户陷入收集疲劳;铸主维度的核心是"了解",不是"集齐"

---

## Designer pushback to Researcher

**Researcher 提议的"铸造者档案 + 关系图谱"形态,我完全保留**,但补充一个关键认识:

**铸主维度不应是"独立 page",而应是"渗透层"** — 类似 rarity-halo 的全局视觉:
- 在每件器物详情页右侧,如有铸主信息,自动浮出该铸主的"迷你卡"
- 在铭文释读器里,识到铸主名字自动浮卡片
- 在场景重建里,集齐某铸主系列触发专属场景

这样铸主维度的"渗透"效应可以放大,而不仅是 P3 优先级的"独立页面"。

**优先级建议**: 在夜跑 Phase 3 demo 中,完整档案卡作为 P2 实现;但"铸主迷你卡"(在 artifact.html 浮窗)可作 P1,因为它的边际效果对所有 persona 都明显。

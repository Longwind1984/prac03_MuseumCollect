# Purpose-Scene — 用途维度 (礼器归位场景)

## One-line purpose
把"用途"从"祭祀礼器"这种文字标签,翻译成**用身体记得的礼制系统** — 用户在一张 isometric 宗庙场景图上拖拽自己收藏的器物到该归的位置,集齐九鼎八簋 → 解锁"天子之礼"。礼制不是知识,是动作。

## Visual description

**多套场景**(每套是一个独立画面),由用户切换或解锁:
1. **太牢祭祀场景**(宗庙)— 主场景,九鼎八簋的列鼎制度
2. **燕飨礼场景**(殿堂)— 簠盨豆觥,宴飨之礼
3. **朝聘礼场景**(朝堂)— 大盘大盂,水器之礼
4. **军礼场景**(军营 / 战车)— 戈矛剑钺,兵器之礼
5. **葬礼场景**(墓道)— 明器,陪葬之礼

每个场景是**等距视角 (isometric) 的礼器布局图**,带毛笔速写风格,有"神主"或"主位"等空间锚点。每个礼器位置是一个**虚线方格(待补)** 或 **实物(已归位)**。

**关键视觉细节**:
- 场景配色: 古铜暗金 + 朱砂红 + 暗青绿 + 米黄底,营造宗庙庄严感
- 已归位件物是**等距 3D 投影的器物图标**(简化但有体积感)
- 待补位是**朱砂红虚线 + 朱砂"位"字**(不是空白)
- 神主 / 主位是场景空间锚点,用篆书或楷书写
- 完成度达 100% 时,场景**亮起所有金光**并切到"天子之礼"宏大全景视图(摄像机拉远,显出整个宗庙建筑)

## Interaction behavior

- **默认状态**: 太牢祭祀场景(默认主场景),用户已收藏件物显示在右侧"待归位"栏
- **Drag 收藏件到场景**: 拖拽时器物图标半透明跟随,合规位置高亮金边
- **Drop 到合规位**: 器物落入位置 → 朱砂虚线变实线 → 金光闪一下 → 位置上方"位"字消失,显示器物名;同步谱系树该子型点亮(组件 B 联动)
- **Drop 到不合规位**: 弹出提示 "此位需 [西周晚期·圆鼎],你拖入的是 [商晚期·方鼎],格不合礼" → 器物回到待归位栏
- **Hover 待补位**: 浮出提示 "此位需 [属性] 的器物。以下 3 件 mock 中符合 → [跳到搜索]"
- **顶部场景切换**: 太牢 / 燕飨 / 朝聘 / 军礼 / 葬礼 — Tab 切换,场景滑动
- **Click 已归位器物**: 跳转到该器物详情页
- **达成完整礼制动画**: 完成 100% → 场景金光化 + 摄像机拉远 + 文案 "天子九鼎八簋,礼制具足" + 解锁"天子之礼"特殊视图

## Data requirements

**Required fields from `bronze-treasures-v1.json`**:
- `purpose`(祭祀礼器 / 盛酒礼器 / 盥洗礼器 / 兵器 等)
- `form_subtype`(用于判断"该器物是否能归到此位")
- `dynasty` + `period`(用于断代合规检查)
- `id`、`name_zh`

**Derived data**:
- `scene_definitions[]` — 5 套场景的位结构(共多少位、每位需要的器物属性 [form_subtype, period, size_min, size_max])
- `scene_completion{scene: %}` — 每个场景完成度
- `position_constraints` — 每个位置的属性约束(由 Designer + Researcher 提供)

**User state**:
- `user.scene_placements{scene: {position_id: artifact_id}}` — 用户的拖拽放置状态(保存,刷新不丢)
- `user.unlocked_scenes[]` — 已解锁的特殊场景(天子之礼等)

## Game mechanic hook

- **Completion 是有等级的**: 不是"完成 / 未完成",是"诸侯之礼 / 大夫之礼 / 士之礼 / 天子之礼"四档,根据归位件物数 + 件物等级判定。每升一档场景视觉发生变化(神主放大、灯火更亮)
- **Story 故事感**: 礼制不是"集齐",是"周礼· 王道篇 / 大夫篇 / 士礼篇"5 段叙事,每解锁一段揭示一段历史(列鼎制度起源、九鼎传说、问鼎中原典故)
- **Connection hook**: 场景中的器物可点跳详情,场景就是导航器;Drop 一件 → 谱系树同步点亮(双向绑定,见 form-genealogy.md)
- **空位即诱发**: "鬲位待补,场景需要一件商-西周早期的鬲来煮粥献神" → 用户直接被引到搜索
- **多场景的解锁顺序**: 默认开太牢,集齐 3 件解锁燕飨,集齐 5 件解锁朝聘...,渐进解锁

## Implementation hint

- **Tech**: SVG 场景画面(等距网格 + 位锚点)+ HTML5 drag-and-drop 或更稳的 react-dnd 替代;framer-motion 做归位动效
- **Approximate complexity**: moderate-hard(等距视图的视觉是工作量,拖拽逻辑标准)
- **Libraries**: framer-motion 用于动效;HTML5 native drag-drop 或 interact.js;Tailwind 用于面板
- **Mobile considerations**: 移动端拖拽用 long-press 触发 + 触摸拖动;场景在移动端切换为 tap-to-place(点击位 → 弹出"选择件物" 列表)

## Cross-component connection

1. **形制 × 用途(组合 B)**: 与 `form-genealogy.md` 双向绑定(产品最重要的跨组件协同)。详 motivation-hooks.md §3.2。
2. **稀有度光晕**: 国宝级件物归位时,该位金光更强烈;集齐全国宝的场景有专属"国之重器·天子之礼"金色全景
3. **时代联动**: 不同场景默认显示不同朝代版图(太牢主西周,燕飨主春秋,军礼主战国)
4. **铸造者**: 集齐"妇好系"件物 → 解锁专属"妇好祭祀场景"(殷王武丁王后的私人祭礼)

## Persona differentiation

- **A 考据派**: 场景配文案严谨,文献依据可见 — "《周礼·秋官》: 天子九鼎,诸侯七鼎,大夫五鼎,士三鼎"出处直接显示在场景下方;场景中每个位置可查"该位的考据由谁定的";支持"按文献复原 / 按出土复原" 两种场景版本切换
- **B 沉浸派 ★(这是 Builder B 的杀手锏)**: 场景是**沉浸式插画风格** — 火光跳动(CSS animated flame),远处有编钟轻响占位音效,祭司剪影站在神主旁;归位一件器物有"敬献"动作 + 火光摇曳;完成时全场景金光化 + 一段叙事文案"商王武丁的祭祀大殿,今夜灯火通明..."
- **C 探索派**: 场景做成关卡式 — 顶部进度条 "BOSS: 天子之礼  7/15";完成有"FANFARE +1000 经验"提示(可关);场景可直接生成"我的祭祀大殿"截图 + "我已完成 47%" 分享卡;有"挑战模式"(限定 5 分钟集齐)等彩蛋

## Don't do these

1. **不要做成"角色装备栏式拖拽"** — 礼器归位是仪式,不是装备槽;视觉语言必须根植于宗庙/朝堂,不是游戏 UI
2. **不要把"完成度"做成单纯百分比** — 等级感(诸侯 / 大夫 / 天子) 远比 47% 有意义
3. **不要让场景背景是纯色 / 渐变** — 场景需要叙事感(灯火、剪影、空间深度),纯色背景会让它沦为"功能页面"
4. **不要把不合规拖拽做成红色错误提示** — 应该是"格不合礼"这种语义化的、有教化感的反馈

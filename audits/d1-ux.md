# UX Audit — Day 1 — Cold-Context Review

> Reviewer: 硬核博物馆爱好者(逛过国博、故宫、湖北省博、三星堆、晋博、苏博 二十余次,自己有 Notion 文物笔记)。
> 第一次打开这三个 demo,没人给我介绍。我只看 README 标题、`index.html`、`catalog.html`、`artifact.html`、`me.html`,然后才点其他维度页。
> 评估时间窗:每个 demo 给自己 5 分钟"决定要不要继续用"。

## Demos reviewed
- `demos/v1-A-textual-research/` (考据派, persona A 陈翊安)
- `demos/v1-B-immersive/` (沉浸派, persona B 苏念)
- `demos/v1-C-explorer/` (探索派, persona C 阿K)

---

## My snap impression (first-time user)

**A — 考据派 / 青铜考**:打开 `index.html` 第一眼是"卷首 · Volume I",右上角"持照人 陈翊安 / 北京大学 / 护照号 甲编 No.00837"。我心里"嗯?"了一下 —— **它直接预设我是陈翊安**,而不是让我成为我自己。米黄纸底 + 衬线宋体 + `[1]` 引用上标,确实一秒切入"学术期刊"气质。但我作为一个硬核但非学者的爱好者,被"持照人"这个固化身份挡了一下 —— **它在 0 秒就告诉我"如果你不是博士生,这里不是你的家"**。

**B — 沉浸派 / 青·铜**:`index.html` 是深黑底 + 大字"穿过那一道青铜的门" + 慢动画 ken-burns。第 1 秒我会停下来 —— 它**像电影预告片**。但当我开始滚动,发现整个落地页有 5 个 hero section 堆叠(hero / 今日国宝 / 三道入口 / 已唤醒 / 收束诗),**每个 section 都 `min-h-screen` 或接近**,我滚了 4 屏才看到"已唤醒 8/25"的卡片。**美,但功能性入口被诗意稀释了**。

**C — 探索派 / 青铜图鉴**:`index.html` 加载后那张 hero card **自动翻面**(JS 里 `setTimeout 350ms`),露出妇好鸮尊金光晕。第 2 秒我就懂"这是一张可以收集的卡"。下方 4 个 stats(7/25 件、国宝率 100%、4/7 朝代、47 字)同屏可见,**信息密度恰当**。我作为一个见过太多博物馆 App 的人,**第一反应是"这个排版我看过太多 —— 但它把'国宝率 100% (行业 4%)'放进 stats 里这个对照是新的"**。

## Critical UX observations

### A — 考据派

**1. Findability** — 整体导航靠 `js/layout.js` 注入的 header(我没读 layout.js 但从页脚一致性看出来),`index.html` 主体明确给了 3 个维度入口的卡片(`time-pillar` / `ancient-map` / `pattern-tree`),还附带覆盖率进度条。**问题**:`catalog.html` 的"三视图切换"用了 tab(`按朝代/出土/形制`),tab 视觉很弱 —— 灰色文字 + 朱砂细下划线,我第一遍滚动时**完全没注意到这是 tab**,以为是面包屑。这是 P1 级 findability 问题。

**2. Information layering** — `artifact.html` 一口气塞了铭文释读器 + 同型对照墙 + 时空柱位置 + 出土地图 + 拓片放大镜 + 出处引用表 + 跨参照推荐 —— **七层并列**,每个都默认展开。对陈翊安(假定她真的存在)而言这是"深度优先,纵向钻取"的正确姿态;对一个第一次访问的我而言,**信息瀑布过重 —— 我无法判断"应该先看哪个"**。没有信息层级的优先级提示。

**3. Empty states** — 整个 demo 假定我已经收藏了 9 件。**完全没有"如果我是 Day 1,0 收藏的人,这页长什么样"的状态**。我去看了 `me.html` 的"待补研究断面"区,文案是"您已覆盖范铸法 9 件,但失蜡法 0 件"—— 如果我 0 收藏,这一整页应该是什么?**没有答案**。这是 P0 风险。

**4. Error states** — `scan.html` 是这版做得最好的一页 UX:有 8 个 mock 样张覆盖"高清/侧光/展签/铭文/低置信度/无匹配"6 种情境,每张返回不同结果,**置信度低时呈现多候选 + 搜索回退,并明示"诚实做法"**。这是符合考据派"AI 不黑盒"诉求的 UX。其他页面没有 error state(空数据、网络失败等都没有处理)。

**5. First 60 seconds** — 我作为非陈翊安的用户,前 60 秒会做的事:扫一眼"个人案卷"(发现这不是我的)→ 看三大维度卡片(理解了)→ 想点"导出研究笔记 (Markdown)"按钮(因为它最有"权威感")→ 跳到 artifact.html 看毛公鼎 → **被铭文释读器吸住** —— 这是 A 的杀手锏。**没有任何引导,但确实自然走到了核心 wow 点**。然而**第二次会不会回来,取决于我能否克服"我不是陈翊安"的违和感**。

**6. Mobile readiness** — 用了 Tailwind 的 `md:` 响应式 grid,页面在窄屏会塌成单列。但 `artifact.html` 的"同型对照墙"是 `grid-cols-2 md:grid-cols-4` —— 在手机上变成 2 列时,对照墙的"横向并排"语义会断。表格(`scholar-table`)在手机上必然要横向滚或丢字段,**对一个数据密度极高的考据派而言这是结构性问题**。

### B — 沉浸派

**1. Findability** — 这是三版里 findability **最差**的。`index.html` 没有顶部 nav 显式入口 —— 只有 hero 区底部两个按钮("入·图鉴" / "唤·醒一件")。**我必须滚 5 屏才能找到"古国图""礼器归位""时空柱"的入口**,而且这三个入口长得像"诗意装饰",不像"功能 tab"。在 `me.html` 没有 sticky nav。我多次需要"按浏览器后退键"才能回去。

**2. Information layering** — 完全相反的问题:每屏信息量太低。`artifact.html` 平均一屏只有 1 张图 + 1 句诗 + 1 段独白,**滚完一件文物需要 12-15 次空格键**(hero / 独白 / 场景 / 五段时光卷 / 工艺长卷 / 铭文 / collect action / 相关推荐)。这对小红书截图很好,**但对"想快速查一件鼎是什么时候的"的硬核用户来说是痛苦**。

**3. Empty states** — 同 A,假定我已唤醒 8 件。当我看到首页"已唤醒 8 / 25"我感觉良好;但**如果我 0 唤醒,整个"已唤醒"section 应该是什么?那张"苏念之卷"的红色印章(`me.html` 第 19 行)在我 0 唤醒时应该叫什么?** demo 没回答。

**4. Error states** — `scan.html` 有 loading state("正在唤醒 / 它埋了三千年,这一两秒值得等"),四种情境都用诗意语言包装。对 nomatch 状态文案("无法认出 / 换一张"),**诗意保住了**。这是这版做得好的地方。

**5. First 60 seconds** — 极致美的开场,但 60 秒后我可能还停留在 hero 区或"今日国宝"section,**我离"我已唤醒哪些"这个核心收藏面板还有 3 次 scroll**。如果我是一个目标明确的用户("我想看看我有没有妇好鸮尊的笔记"),B 会让我感到"找东西要费力"。

**6. Mobile readiness** — **这版的 P0 问题**:几乎所有页面都用 `px-20`(80px 左右内边距),而且很多容器是 `max-w-5xl` 或 `max-w-6xl` —— 在手机上 80px 单边内边距会吃掉 40% 屏宽。诗意排版(`letter-spacing: 0.5em` 大量出现)在手机上一行可能就剩 3-4 个字。**移动端需要重新设计**,不是简单缩放。

### C — 探索派

**1. Findability** — 这是三版里 findability **最好**的。所有页面都有 sticky `top-nav` 含 5 个固定入口(图鉴/时空柱/古国地图/形制谱系/扫描)+ "我的"按钮。任何时刻我都知道自己在哪、能去哪。`catalog.html` 的 tab 视觉强、有 hover 反馈,filter chips("全部/仅看国宝/仅看已收")清晰可点。

**2. Information layering** — `index.html` 把"今日推荐 / 我的进度 / 3 维度入口 / 本周新点亮 / 下一步诱发"放在 5 个 section 内,**每个 section 都在 1.5 屏内可读完**。`artifact.html` 用"5 个维度卡片"网格(时代/出土地/馆藏地/铭文/形制),每张卡片是这件文物在该维度的位置缩略图 + "→ 进入详图"链接。**这是三版里最让我感到"我能控制信息深度"的设计**。

**3. Empty states** — 同 A、B,假定已收藏 7 件。但 C 至少有**剪影态**:`catalog.html` 给未收藏的文物画了灰色剪影(`silhouette-wrapper` CSS),并标注"待踏足"。这比 A、B 都好,因为它**视觉化了"未来要做什么"**。然而 Day 1(0 收藏)整个 Pokédex 全是剪影时,会是什么体验?**也没回答**。

**4. Error states** — `scan.html` 的 reveal sequence(900ms 弹簧动画 + 揭示卡片 + 国宝光晕)+ confidence band(high/medium/low/no_match 都有不同视觉)是这版最 polished 的交互。**nomatch 兜底文案"试试搜索"很合适**,不会让用户觉得"AI 蠢"。但是 — **整个 demo 没有处理"我点错了""我想撤回收藏"的 error state**。

**5. First 60 seconds** — Hero card 自动翻面 → 我看到妇好鸮尊金光卡 → 想点"扫一扫开卡"(因为按钮颜色比"浏览图鉴"更亮)→ 进 `scan.html` 看 reveal sequence → **wow 点达成**。**60 秒内完成"理解产品 → 体验核心机制"的闭环**,这是 C 的胜利。

**6. Mobile readiness** — 用 Tailwind 响应式;`max-w-6xl mx-auto px-5` 是合理的容器策略;sticky 顶部 nav 在窄屏会塞 6 个 link 略拥挤但能用;`grid-cols-2 md:grid-cols-4` 模式让卡墙在手机变 2 列时仍然可读。**三版里移动端落地成本最低**。

## Things present that don't earn their place (UX overhead)

**A 版:**
- `index.html` 右上角整个"个人案卷"侧栏(`持照人/单位/护照号/录入文物/...8 个字段`)—— 信息密度太高,**对未签到的新用户而言这是噪音**。
- `artifact.html` 同时展示"时空柱位置 mini + 出土地图 mini" —— 二者都是缩略到不可交互,**它们应该是一个"5 维度雷达图"的合并视图**,而不是两个 mini-component 占满半屏。

**B 版:**
- 大量装饰性"诗意"文案出现两遍 —— `index.html` 顶部"等过三千年,你来看我" + 底部"它们在等一个肯停下来的人。你今晚来了。"这种**风格化重复**第一次有效、第三次就成噪音。
- "贵宾印章 / 流散篇 / 朝圣护照"在 `me.html` 和 `ancient-map.html` 都出现,功能略有重叠 —— **新用户搞不清楚二者关系**。
- `artifact.html` 的"音频朗诵"占位 + 波形 SVG —— **既然是 mock 没有真音频,不如不放占位**,放一个"敬请期待"的说明更诚实。

**C 版:**
- `index.html` 那个"📖 故事"(`storyText` 占位符)写了 emoji —— 与产品其他位置"克制 = 高级"的设计调性不一致,**像 placeholder 没换掉**(在 me.html 第 171 行也有 `🌿`)。
- `me.html` 的"复制图鉴"按钮没说清复制的是什么(链接?截图?分享文案?)—— **labeled but undefined**。
- `form-genealogy.html` 的右侧"Unlocks"区里"百工之祖 · 工艺集齐 2/7"—— **没看到任何地方解释这 7 个工艺是什么**。

## Severity ranking

### P0 — Blockers

1. **三版都缺 Day 1 / 0-state**:新用户进来直接被预设角色(陈翊安 / 苏念 / 阿K),严重破坏代入感。**这是 demo night 之后第一件要补的**。建议:增加"首次进入"流程 —— 选一个昵称、可选关联手机号、看一个 30 秒的产品价值视频 / interactive walkthrough。
2. **B 版 移动端不可用**:`px-20` + 大量 fixed-pixel 装饰 → 手机端必然崩。如果产品定位是"博物馆现场用"(PRD §1 痛点 1),**B 不可作为移动端基础**。
3. **三版段位 / 称号 / 国宝率口径不统一**:同一数据池在三个 demo 里给出三套数字。如果走"merged 路线",必须先定义一套统一的 progress 语言。

### P1 — High friction

4. **A 版 `catalog.html` tab 视觉太弱**:看不出是 tab,容易错过。换成有背景色的 pill 即可。
5. **B 版 findability 太弱**:落地页 5 屏才到收藏入口。建议把"我已唤醒 8/25"这个状态做成 sticky 顶部小条 + 直跳 `me.html` 的链接。
6. **A、C 版未收藏文物的"点击行为"不明确**:点剪影会进 `artifact.html?id=...` 还是进"候选介绍页"?demo 都是直进详情页 —— 但是**详情页的国宝独白 / 铭文释读对未收藏的用户应该折叠 vs 直露,没人想清楚**。

### P2 — Nice-to-have

7. C 版 emoji 与设计调性不一致。
8. B 版"音频朗诵"占位移除或改诚实。
9. A 版 `artifact.html` 多组件并列应该有"折叠面板"控制。
10. 三版顶部 nav 都没有 breadcrumb(C 的 nav 至少有 active state 高亮,A、B 都没有)。

---

## Bottom-line ranking (UX only)

1. **C 探索派** — UX 完成度最高。findability 强,信息层级合理,wow 点 60 秒内可达,移动端落地成本低,剪影态是"未来要做什么"的最佳可视化。**最大的隐忧是"克制游戏化"还不够克制 —— 三个 stat panel 同屏(7/25 + 100% + 4/7 + 47字)对纯小白来说仍然过度量化**。
2. **A 考据派** — 对它的目标用户(博士生 / 学者)而言可能是最贴切的 UX,但对"硬核但非学者"的大多数核心用户而言**门槛过高**。`artifact.html` 信息密度处理得很有思考但还需要分层。**最大的杀手锏(铭文 hover + 段位制)需要被新手用户走到才能见到**,需要"非破坏式引导"。
3. **B 沉浸派** — 美学第一,UX 最末。**它是一个非常适合做产品宣传片的设计,不是一个适合每周打开的工具**。移动端基本要重做。findability 短板尤其严重 —— 一个用户要打开 5 屏才能"用"它,这是结构性问题。
